# EXCHANGE LOG — {{PROJECT_NAME}}

Every document that entered or left this project, in date order (rule R4). This
is the index of the conversation, the way `INDEX.md` is the index of the files.

**This file is a view. `LOG.jsonl` is the record.** Rows are added with
`05_tools/log.py add` and the table below is regenerated from the JSONL; typing
into the table changes nothing that a query will ever see. The split exists
because a works contract runs for years and produces thousands of events, and a
markdown table cannot be filtered, counted or sorted at that size.

One row per **event**, not per file. A revision that was superseded keeps its
row — it is not deleted, it is marked `superseded by #n` and the new revision
gets a row of its own. That is what makes "what did we send them on the 24th,
and what came back" answerable without opening anything.

Rows are written **at the moment of the event**, dated from the document's own
face. A log reconstructed afterwards from file timestamps is a guess, and it is
a guess about exactly the facts someone will later dispute. The one exception
is backfill — a batch filed after the event, off an old drive or from a
predecessor — and a backfilled row says so: `--backfilled` on the way in, a
`†` beside its date in the table below.

```bash
python3 05_tools/log.py add --date 2026-08-18 --dir in --party "ACME" \
    --type letter --doc "Notice of delay" --ref "ACME-L-0142" \
    --path 03_exchange/received/ACME/2026-08-18_notice-of-delay.pdf \
    --thread delay-claim --action open --due 2026-09-01
python3 05_tools/log.py add --date 2026-08-25 --dir out --party "ACME" \
    --type letter --doc "Reply to notice of delay" --ref "T-0031" \
    --path 03_exchange/issued/ACME/L-0088.pdf --thread delay-claim --answers 12
python3 05_tools/log.py query --action open        # what is owed, either way
python3 05_tools/log.py query --party ACME --dir out --since 2026-01-01
python3 05_tools/log.py check                      # the log against the tree
```

Columns:

- **Dir** — `in` for received, `out` for issued. The whole point of one table is
  that both directions sit in one chronology. Direction is also the folder
  (R1), and `log.py` refuses a row whose direction contradicts the folder its
  file sits in.
- **Party** — who it came from or went to, by the label in
  `00_AI_context/PARTIES.md`. Filtering this column is how a project with
  several counterparties is read.
- **Type** — `letter`, `drawing`, `boq`, `report`, `po`, `vo`, `instruction`,
  `submittal`, `minutes`, `transmittal`, `invoice`, `programme`, `email`,
  `contract`, `amendment`, `notice`, `rfi`, `application`, `certificate`,
  `claim`, `other`. An unlisted type is accepted; it just gets a warning.
- **Rev** — the sender's own revision, not an internal one. It is what the other
  side will cite.
- **Ref** — outbound: the transmittal, covering letter or portal submission.
  Inbound: their document number, or how it arrived. An email typed up into a
  markdown file rather than filed as it arrived says `email (transcript)`,
  because what the project holds is a copy and the row should not imply
  otherwise.
- **Status** — two states in one cell, because they answer two questions. The
  document's state: `current`, `superseded by #n`, `withdrawn`. Then, after a
  `·`, what is owed on it: `open`, `answered by #n`, `closed`, or nothing —
  with the due date if one was set. On an `in` row `open` means we owe the
  reply; on an `out` row, they do. The Outstanding list below is derived from
  it.

Path and note stay in the JSONL — `query --paths` prints the path. Path names
what was filed: for an issued document, the PDF (its source sits beside it
under the same stem, R10); for a multi-file event, the folder.

An executed contract or subcontract still gets a row here for the day it became
executed, even though the instrument itself is filed in `01_contract/` (R1).
The log is the chronology of everything that moved; it is not a second copy of
the filing system. Reference material in `02_basis/` gets no row — it has no
direction and no party — and internal-only documents are listed in
`00_AI_context/PROJECT.md`, not here: this log is the conversation, and they
were never part of it.
